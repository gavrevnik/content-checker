# whatsNew

Локальная библиотека фильмов и музыкальных альбомов с бэклогом, оценкой просмотренного/прослушанного и персональными рекомендациями. Активные данные хранятся в SQLite, интерфейс работает на `127.0.0.1`. Фильмы обновляются через TMDB, OMDb и Kinopoisk API Unofficial, альбомы и исполнители — через публичный read-only MusicBrainz Web Service API v2, фотографии исполнителей — через fanart.tv, а количество прослушиваний — через ListenBrainz Popularity API.

Однокликовый переключатель-плашка «Фильмы / Музыка» доступен в бэклоге, просмотренном, персонах, избранном и корзине; «Избранное» в левой навигации расположено сразу после «Персон». Экраны библиотеки не дублируют название текущей вкладки отдельной верхней шапкой. В бэклоге слева сгруппированы переключатель и счётчик; справа остаются «✦ Подобрать похожее», «↻ Новое от авторов», дополнительные действия и поиск. Действия «＋ Добавить вручную» и «⟳ Обновить» скрыты в меню `…`; аналогичное меню используется на вкладке персон. На вкладке «Просмотрено» переключатель и поиск находятся внутри общей рамки тулбара без изменения их расположения. Прозрачный логотип отображается крупным знаком над названием WhatsNew в центрированном винтажном бренд-блоке боковой панели и как favicon вкладки браузера. Общий слой `content_items` хранит статус и реакцию, а таблицы `movies` и `albums` разделяют данные провайдеров.

## Запуск

Один раз подготовьте локальное окружение для LLM-рекомендаций:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
codex login status
```

Последняя команда должна вывести `Logged in using ChatGPT`. Если авторизации ещё нет, выполните `codex login` и завершите вход через браузер.

После этого на macOS откройте двойным кликом `Whats New Checker.app` или выполните:

```bash
python3 app/server.py --open-browser
```

Адрес приложения: `http://127.0.0.1:8765`.

`.app` запускает сервер как отдельный фоновый процесс и при каждом повторном клике открывает новую вкладку с localhost. Launcher проверяет в `/api/health` идентификатор приложения и версию: предыдущую версию `app/server.py` этого репозитория он безопасно перезапускает, а при занятом посторонним приложением порте останавливается с понятным сообщением и не открывает чужую страницу. Диагностический журнал пишется в `.runtime/server.log`.

Основное приложение использует стандартную библиотеку Python 3. Для LLM-вызова официальный Codex SDK установлен из `requirements.txt` в локальную `.venv`, которая не попадает в Git.

Сервер не реализует учётные записи и аутентификацию: границей безопасности служит привязка к `127.0.0.1` по умолчанию. Не запускайте его на внешнем интерфейсе через `--host 0.0.0.0` без отдельного защищённого прокси и контроля доступа — JSON API содержит операции изменения и безвозвратного удаления данных.

## Архитектура

- `app/server.py` — многопоточный HTTP-сервер на стандартной библиотеке Python. Он раздаёт статический интерфейс и внутренний JSON API: чтение библиотеки, персон, корзины и конфигурации; добавление, обновление и восстановление объектов; запуск рекомендаций, обновлений провайдеров и отмену длительных операций.
- `app/storage.py` — единый слой доступа к SQLite. При штатном запуске он создаёт отсутствующие таблицы и применяет встроенные совместимые обновления схемы; активные данные не импортируются из `legacy/` автоматически.
- `app/tmdb.py`, `app/musicbrainz.py`, `app/listenbrainz.py` и `app/fanart.py` инкапсулируют внешние источники, а `app/artwork.py` отвечает за безопасные локальные пути и кэш изображений.
- `app/llm.py` формирует контракты рекомендаций, вызывает изолированный runner `scripts/run_codex_recommendation.py` и проверяет структурированный ответ; `app/recommendation_progress.py` хранит в памяти прогресс, предупреждения и флаг отмены текущих операций.
- `app/static/index.html`, `app/static/styles.css` и `app/static/app.js` образуют vanilla HTML/CSS/JavaScript-интерфейс без frontend-фреймворка. Ответы на мутации возвращают актуальные записи хранилища, а перезагрузка интерфейса восстанавливает состояние из SQLite; пояснения временных рекомендаций не становятся частью библиотеки без отдельного пользовательского действия.

Маршруты `/api/*` являются внутренним контрактом между локальным frontend и backend, а не отдельным публичным API. `/api/health` возвращает идентификатор и `APP_VERSION`, `/api/meta` — доступность интеграций, остальные маршруты сгруппированы вокруг `/api/library`, `/api/people`, `/api/trash`, `/api/recommendations` и `/api/backlog/moods`. При несовместимом изменении frontend/backend-контракта нужно увеличить `APP_VERSION` в `app/server.py`, чтобы launcher обнаружил и перезапустил устаревший локальный сервер.

## Интерфейс

### Бэклог

Переключатель в левом краю тулбара меняет фильмы на музыкальные альбомы одним нажатием. Для альбомов таблица показывает небольшую обложку, название с исполнителем второй строкой, первый выпуск, количество песен, общее количество прослушиваний ListenBrainz, ссылку поиска альбома в YouTube Music и дату добавления в локальную базу. Тип и жанры остаются в подробной карточке. Кнопки реакции сразу переносят альбом в прослушанное, корзина работает обратимо. Добавлять фильмы и альбомы можно только из бэклога.

Таблица показывает небольшой постер, русское и оригинальное название, дату выхода, режиссёра в формате `русское имя (original name)`, объединённую оценку `IMDb / КП`, страны, ключевых персон и дату добавления в локальную базу. Колонка «Добавлено» расположена непосредственно перед колонкой CalendarCheck и сортируется по дате; первый клик показывает новые записи сверху. Отдельной колонки `Link` нет: ссылки КП и RuTr расположены прямо под парой названий фильма. Жанры остаются в подробной карточке. RuTr ведёт на поиск RuTracker по русскому названию и году фильма. Если рейтинга Кинопоиска нет, значение выглядит как `7 / —`. TMDB ID убран из таблицы и остаётся в подробной карточке. Ключевые поля сортируются нажатием на заголовок. В компактной колонке ключевых персон показывается только русское имя без оригинального имени в скобках и без подписи роли, например `Николас Кейдж и др.`. Поиск по бэклогу учитывает русское и оригинальное название, режиссёров, страны и всех ключевых персон. Карточка открывается кликом по названию фильма и также содержит ссылку RuTr. Увеличенные шрифт, межстрочный интервал и отступы делают таблицы удобнее для чтения, сохраняя горизонтальную прокрутку на узких экранах. Контурные кнопки лайка и дизлайка сразу переносят фильм в соответствующую колонку раздела «Просмотрено»; нейтральная кнопка корзины становится красной только при наведении и выполняет обратимое удаление. CalendarCheck в отдельной компактной колонке помечает фильм или альбом для ближайшего просмотра/прослушивания, подсвечивается золотистым цветом и позволяет вывести отмеченные позиции первыми; при оценке произведения отметка автоматически снимается. Длинные списки ключевых персон сокращаются до первой персоны и пометки «и др.», но в карточке доступны полностью.

Над таблицей бэклога, сразу под панелью действий, расположен блок «Настроение фильмов/альбомов в бэклоге» с максимум 15 категориями в двух горизонтально прокручиваемых рядах; полоса прокрутки скрыта, но прокрутка трекпадом и колесом мыши работает. Кнопка «Обновить» просит Codex SDK проанализировать весь текущий бэклог и вернуть структуру `настроение → локальные ID подходящих позиций`. Сервер проверяет ID и атомарно заменяет сохранённую карту в таблицах `backlog_moods` и `backlog_mood_items`; она восстанавливается после перезагрузки приложения и остаётся активной до следующего успешного обновления. Ошибка или отмена LLM-запроса не затирает предыдущую карту. Нажатие на чипс оставляет в расположенной ниже таблице только перечисленные для него фильмы или альбомы — приблизительного поиска по словам нет. Активным может быть только один чипс: выбор нового автоматически снимает предыдущий, а повторное нажатие возвращает полный бэклог. Если связанная позиция уже покинула бэклог, при чтении карты она автоматически исключается из фильтра.

В таблицах результатов «✦ Подобрать похожее» и «↻ Новое от авторов» справа над выдачей доступна кнопка увеличения. Она скрывает формы и фильтры текущего запроса, растягивает таблицу на свободное пространство модального окна и временно убирает нижнюю таблицу не прошедших фильтрацию объектов. Повторное нажатие возвращает исходную компоновку, сохраняя настройки запроса и результаты.

«Актуализировать из TMDB» выбирает карточки, которые ещё не проходили успешную проверку нужного источника, не имеют TMDB ID или потеряли локальный файл известного постера. Полная карточка TMDB запрашивается только при отсутствии ID или отметки успешной TMDB-проверки; OMDb и Kinopoisk вызываются независимо, только если соответствующий ключ настроен, рейтинг отсутствует и источник ещё не был успешно проверен. Успешный ответ «данных нет» тоже сохраняется, поэтому допустимо пустые описание, режиссёр, рейтинг или постер не образуют бесконечную очередь запросов. Временная ошибка отметку не ставит и будет повторена позже. Потерянный локальный постер повторно загружается без обновления остальных данных.

В открытой карточке отдельная кнопка «Актуализировать из TMDB» применяет ту же логику только к выбранному фильму. В форме добавления достаточно ввести русское или оригинальное название: актуализация показывает в той же модалке до 10 найденных TMDB-вариантов, отсортированных по близости названия и указанного года. Для каждого варианта показываются локализованное и оригинальное названия, год, язык, рейтинг, описание и локально кешируемый постер `w185`. «Подробнее» загружает полную карточку TMDB/OMDb/Кинопоиска, а «Выбрать» сохраняет именно этот вариант в бэклог. Уже существующие в библиотеке или корзине варианты помечаются и не выбираются повторно. Ручное добавление без выбора результата, а также контурные кнопки лайка и дизлайка остаются доступны. Кнопка «Очистить» полностью сбрасывает ручной ввод и найденные данные, оставляя модалку открытой; изменение названия или года очищает старую выдачу и запускает новый поиск при следующей актуализации.

Форма альбома аналогично умеет найти и нормализовать запись по названию, исполнителю, году или MusicBrainz ID. В полной карточке доступны обложка, исполнители, первый выпуск, количество песен, типы релиза, жанры и теги, количество прослушиваний ListenBrainz, страна, лейбл, каталожный номер, штрихкод, формат носителя, статус конкретного издания и трек-лист. Альбом хранится как MusicBrainz `release-group`, а сведения конкретного издания берутся из выбранного официального `release`. Кнопка актуализации выбирает альбомы с ещё не выполненной MusicBrainz-, Cover Art Archive- или ListenBrainz-проверкой, а также с потерянным локальным файлом известной обложки. Подтверждённое отсутствие необязательных данных сохраняется и не вызывает повторных массовых запросов; временные ошибки можно повторить позднее. ListenBrainz обрабатывает выбранные карточки одним batch-запросом. Рейтинг MusicBrainz не используется и не хранится. В карточках фильма и альбома поле «Заметка» редактируется двойным кликом: потеря фокуса или `Ctrl/⌘ + Enter` сохраняет значение в библиотеке, `Escape` отменяет изменение.

Кнопки «✦ Подобрать похожее» и «↻ Новое от авторов» открывают одну модалку сразу в режиме LLM либо API соответственно; дополнительного переключателя внутри модалки нет. Чтобы не потерять введённый запрос или результат случайным кликом, эта модалка не закрывается нажатием на фон или клавишей Escape — закрыть её можно крестиком. В режиме LLM доступны минимальные рейтинги IMDb и Кинопоиска, диапазон лет, минимальная длительность, максимальное количество рекомендаций и свободный запрос. Каждое формальное условие можно отключить галочкой. IMDb по умолчанию ограничен значением 7, Кинопоиск также имеет значение 7, но изначально выключен, а максимальное количество рекомендаций равно 5. Условия передаются модели в системных инструкциях; после TMDB/OMDb/КП они проверяются повторно. Для Кинопоиска постпроверка мягкая: известная оценка ниже порога исключает фильм, но отсутствие КП-оценки не скрывает рекомендацию и отображается пустым значением. Перед отправкой приложение автоматически добавляет в системный контекст случайные выборки понравившихся фильмов и любимых актёров/режиссёров как мягкий сигнал, а также полный список уже добавленных фильмов, включая бэклог, просмотренное и корзину, как жёсткий список исключений. Максимумы для произведений и персон задаются раздельно в модалке; при каждом открытии они равны текущему количеству соответствующих записей в хранилище, то есть по умолчанию используется весь доступный контекст. Кнопка «Посмотреть промпт» показывает итоговый динамический контракт с фильтрами и контекстом до отправки модели. После ответа Codex рядом с результатами появляется кнопка «Сырой ответ модели», открывающая исходный JSON до обогащения и фильтрации. Колонки таблицы рекомендаций сортируются в обоих режимах.

Codex возвращает строго структурированный JSON: русское и оригинальное название, год и персональный комментарий. Сервер разбирает его, находит каждый фильм в TMDB, дополняет карточку сведениями TMDB/OMDb/Кинопоиска, повторно проверяет включённые фильтры и исключает дубли. В режиме API TMDB используются фильтры по актёрам, режиссёрам, IMDb/КП, голосам, диапазону лет, длительности и жанрам, а поле «Макс. фильмов» ограничивает размер результата. Верхняя граница года применяется до загрузки подробных карточек. Списки актёров и режиссёров при каждом открытии сброшены; без выбора хотя бы одной персоны запрос не запускается. IMDb и Кинопоиск включены со значением 7, а фильтр минимального количества голосов по умолчанию выключен. Английские и русские названия исключаемых жанров нормализуются, поэтому `Animation, Documentary` исключает в том числе локализованные жанры «мультфильм», «анимация» и «документальный». В обоих режимах основная таблица показывает прошедшие проверку карточки, а ниже раздел «Не прошли фильтрацию» повторяет отклонённые сущности отдельной таблицей. В режиме «Новое от авторов» записи вне выбранного диапазона лет не попадают в этот список, а сводка имеет вид «За период 2020–2026 найдено X фильмов, не прошли фильтрацию Y». Кнопка «Подробнее» справа открывает компактное окно со списком `название — причина`; это одинаково работает для фильмов и музыки. Уже находящиеся в библиотеке или корзине фильмы туда не попадают; любую другую отклонённую карточку можно вручную добавить в бэклог. Название открывает подробную карточку, кнопки «В бэклог», лайка и дизлайка сохраняют фильм, а серая кнопка «Убрать» удаляет строку только из текущей выдачи. Все действия над карточками — добавление, перенос, удаление из выдачи и восстановление — используют единый отклик на нажатие, защищены от повторного клика во время запроса и плавно скрывают карточку после успеха. В API-режиме колонка «Заметка» скрыта. Прогресс в обоих режимах показывает ключевые стадии поиска: запрос к LLM или выбранных персон, а затем обработку карточек. После загрузки итоговой таблицы выполненные индикаторы автоматически скрываются.

Для музыки та же модалка предлагает режимы LLM и MusicBrainz API. LLM получает отдельно ограничиваемые в форме случайные выборки понравившихся альбомов и любимых исполнителей, полный список уже добавленных и находящихся в корзине альбомов, диапазон лет и свободный запрос; по умолчанию оба максимума равны текущему количеству записей в хранилище, а структурированный результат независимо уточняется через MusicBrainz. Формальные фильтры можно отключать галочками, а итоговый промпт доступен до запуска. API-режим запрашивает у MusicBrainz до 100 release groups на каждого выбранного исполнителя, применяет год, типы, исключаемые фрагменты названия, дедупликацию и общий рейтинг кандидатов, после чего загружает полные карточки только для первых `Макс. альбомов`. По умолчанию исключены все специальные вторичные типы MusicBrainz: Compilation, Live, Remix, Soundtrack, DJ-mix, Audio drama, Audiobook, Demo, Field recording, Interview, Mixtape/Street и Spokenword, а также названия, содержащие `Deluxe` без учёта регистра. Оба списка исключений можно изменить или отключить. Поэтому значение 20 ограничивает дорогую детализацию и ListenBrainz двадцатью альбомами, но не discovery-ответ каждого исполнителя. Отфильтрованные альбомы также показываются с причинами в нижней таблице и доступны для ручного добавления в бэклог; уже имеющиеся в сервисе альбомы из неё исключены. Прогресс отдельно показывает запрос к LLM либо поиск по исполнителям, загрузку карточек MusicBrainz, обложек Cover Art Archive и статистики ListenBrainz; ошибки источников появляются в панели предупреждений сразу во время обработки, а после загрузки таблицы индикаторы скрываются. Выпадающие списки исполнителей, актёров и режиссёров содержат локальный поиск по имени, расширяются по ширине и высоте вместе с модалкой и закрываются кликом за их пределами или клавишей Escape. Без прокрутки показывается до 15 персон, последующие записи прокручиваются внутри списка. Все пользовательские ссылки альбомов, включая колонку `Link` рекомендаций, ведут на поиск в YouTube Music по названию, году и исполнителю.

Во время LLM- и API-рекомендаций доступна кнопка «Стоп». Прерывание кооперативное: текущий сетевой вызов завершается, следующие этапы и запросы не запускаются, а уже полностью обработанные карточки остаются в результирующей таблице. Такой же индикатор и кнопка доступны при массовой актуализации бэклога; после остановки интерфейс перечитывает библиотеку и показывает количество реально обновлённых карточек.

TMDB является обязательным источником для создания полной карточки: его ошибка показывается пользователю, а соответствующий фильм не добавляется в результаты. Кинопоиск — вспомогательный источник. При известном IMDb ID приложение сначала ищет точное соответствие по нему; если запрос завершился ошибкой или не дал результата, выполняется поиск по названию и году с нормализацией `ё → е`. При исчерпании лимита или другой ошибке обоих вариантов Kinopoisk API карточка всё равно создаётся по данным TMDB/OMDb, а интерфейс показывает предупреждение и оставляет КП-рейтинг и ссылку пустыми.

### Просмотрено

Фильмы разделены на три колонки:

- «Оценить» — реакция ещё не указана;
- «Понравилось»;
- «Не понравилось».

Повторное нажатие текущей контурной иконки лайка или дизлайка снимает реакцию и возвращает карточку в «Оценить». Любую карточку можно вернуть в бэклог. Карточки показывают русское и оригинальное название и постер справа; клик открывает подробные данные. Звёздочка независимо добавляет фильм в избранное и не меняет реакцию, статус или другие атрибуты.

Для музыки используются те же три колонки и механика реакций. Справа в карточке прослушанного альбома показывается его обложка. Звезда независимо добавляет альбом в музыкальное избранное. Кнопки добавления на вкладке «Просмотрено» нет ни для одного типа контента.

### Избранное

Переключатель позволяет открыть режим фильмов или музыки. Вкладка показывает отмеченные звёздочкой фильмы или альбомы: карточка открывает полную информацию, а повторное нажатие звезды убирает объект только из избранного. Маркер сохраняется независимо от перемещений между бэклогом и просмотренным/прослушанным. Отдельного поля поиска на вкладке нет.

### Персоны

Две таблицы содержат любимых режиссёров и актёров: компактное фото профиля, русское и оригинальное имя; TMDB ID скрыт из таблиц и остаётся в карточке. Под портретом показывается ссылка IMDb, если у персоны есть IMDb ID. Внешний ID получается вместе с англоязычной карточкой TMDB через `append_to_response=external_ids`, без дополнительного HTTP-запроса, и сохраняется в `details_json`. TMDB-фото размера `w185` загружается и локально кешируется при рекомендации, ручном поиске и обновлении. Все видимые колонки сортируются нажатием на заголовок; по умолчанию актёры и режиссёры отсортированы по русскому имени, исполнители — по имени MusicBrainz. В форме добавления можно ввести русское или оригинальное имя; TMDB возвращает до 10 релевантных вариантов с фотографией, специализацией и известными работами. «Подробнее» открывает полную карточку с биографическими сведениями, а «Выбрать» сохраняет вариант в указанной роли. Наличие той же персоны в другой роли не блокирует выбор: актёр и режиссёр учитываются раздельно, сохраняя одну общую сущность персоны. Ручное добавление без TMDB-поиска остаётся доступно, первоначально введённые значения сохраняются как `Raw`. Клик по строке открывает карточку, из которой можно полностью актуализировать только выбранную персону через англоязычную и русскую карточки TMDB и TMDB Images. Пункт `… → ⟳ Обновить` обращается к тем же источникам для персон без TMDB ID, IMDb ID, ещё не сверенных персон и карточек с известным профилем, у которых отсутствует локальный файл. Рядом находится кнопка «✦ Рекомендовать похожее»: в LLM-модалке можно переключиться между режиссёрами и актёрами, задать свободный запрос, максимальное количество результатов и максимальное количество любимых персон выбранной роли в контексте. По умолчанию лимит контекста равен числу активных режиссёров или актёров; полный список выбранной роли, включая корзину, остаётся жёстким исключением повторов. Ответ Codex уточняется через TMDB, после чего персону можно добавить из таблицы вместе со ссылкой IMDb под портретом. В результатах рекомендаций клик по доступной фотографии актёра, режиссёра или исполнителя открывает её в отдельном увеличенном просмотре. Контурная кнопка корзины нейтральна в обычном состоянии и становится красной при наведении; она скрывает выбранную роль персоны из активного списка.

В режиме «Музыка» здесь показываются исполнители и группы с типом, страной и фотографией; MusicBrainz ID остаётся внутри карточки. Из уже полученного MBID без дополнительного API-вызова строится ссылка `https://musicbrainz.org/artist/{MBID}`, которая показывается под портретом исполнителя в рекомендациях, списке персон и подробной карточке. При рекомендации, добавлении или актуализации исполнителя приложение запрашивает квадратный `artistthumb` через fanart.tv по существующему MBID, выбирает наиболее популярный вариант и локально уменьшает его системной утилитой macOS `sips` до 200 px перед сохранением в `artwork/people` общего каталога данных; исходный URL и локальный путь хранятся в SQLite. Отсутствие изображения или временная ошибка fanart.tv не блокирует сохранение исполнителя. Исполнителей можно добавить, найти, точечно актуализировать и обратимо переместить в корзину. Пункт `… → ⟳ Обновить` выбирает ещё не сверенных исполнителей и карточки с известным URL фотографии, у которых потерян локальный файл; подтверждённое отсутствие фотографии больше не ставит исполнителя в очередь при каждом запуске. Кнопка «✦ Рекомендовать похожее» открывает LLM-only флоу с лимитом результатов (по умолчанию 5): модели передаются свободный запрос и полный список уже добавленных исполнителей, включая корзину. После ответа модели прогресс отдельно показывает получение карточек через MusicBrainz и загрузку фотографий через fanart.tv.

### Корзина

Переключатель разделяет корзину на фильмы с персонами и альбомы с исполнителями; для каждого режима таблицы и счётчики строятся отдельно. Объекты восстанавливаются одной кнопкой. Обычное перемещение в корзину мягкое: основные записи и связи не уничтожаются, а содержимое учитывается при дедупликации рекомендаций. Кнопка «Очистить всю корзину» после подтверждения безвозвратно удаляет все объекты из SQLite и удаляет их локальные постеры и обложки из общего каталога данных, если эти файлы больше не используются другими записями.

## SQLite

В стандартной структуре `life-stack` активная база находится в `../data/content-checker/library.sqlite3`, а изображения — в `../data/content-checker/artwork/`. Каталог можно переопределить переменной `CONTENT_CHECKER_DATA_DIR`. Описание таблиц и `awards_json`: [`data/SCHEMA.md`](data/SCHEMA.md).

Это единственный активный источник истины. Обычный запуск может безопасно добавить отсутствующие таблицы или колонки через `app/storage.py`, но не пересоздаёт базу из CSV. Для тестов используется временная SQLite-база; живой файл не следует заменять, мигрировать или использовать как тестовую фикстуру.

SQLite хранит URL источника и относительный путь к локальному файлу обложки, постера, TMDB-профиля или fanart.tv-портрета. JPEG находятся в подкаталогах `artwork/albums/`, `artwork/movies/` и `artwork/people/` общего каталога данных и не входят в Git. При отсутствии файла локальный HTTP endpoint повторно загружает его из Cover Art Archive, TMDB Images или уже сохранённого URL fanart.tv и обновляет путь в базе.

Заполнить отсутствующие файлы локального кэша фильмов, альбомов, TMDB-профилей и музыкальных исполнителей можно командой `python3 scripts/cache_artwork.py`. Только фотографии исполнителей загружает `python3 scripts/cache_artwork.py --kind artists`. Чтобы атомарно заменить уже сохранённые крупные изображения новыми `w185`/`front-250`/fanart 200 px, явно запустите `python3 scripts/cache_artwork.py --refresh-existing`; без этого флага существующие файлы не перезаписываются.

Главные таблицы:

- `content_types`, `content_items`, `movies`, `albums` (включая `raw_json` с первоначальным вводом);
- `people`, `interest_roles`, `movie_people` (включая `raw_json`, метаданные и время последней сверки персон);
- `music_artists`, `album_artists` — исполнители MusicBrainz и связи с альбомами;
- `genres`, `movie_genres`;
- `content_aliases`;
- `trash_entries` — маркеры обратимого удаления со снимком названия для экрана корзины.
- `favorite_movies` — исторически названная, но активная таблица независимых отметок избранных фильмов и альбомов.

Первичная SQLite-база была построена из сохранённых CSV. Следующая команда нужна только для осознанного полного восстановления из legacy-снимков, а не для обычного запуска или обновления схемы:

```bash
python3 scripts/migrate_csv_to_sqlite.py --force
```

`--force` полностью пересоздаёт выбранную БД из `legacy/csv/` и удаляет изменения, сделанные после миграции. Не запускайте её против активной базы без явного намерения потерять текущие данные; для проверки указывайте временный путь через `--db`.

Первичное наполнение музыки использует список из `legacy/csv/interests.csv`, скопированный в `data/music_seed_artists.json`, поэтому приложение во время работы не зависит от `legacy/`. Скрипт находит 46 исполнителей и только полноценные альбомы выбранного года: `primary-type = Album` и пустой список `secondary-types` (без Live, Remix, Compilation, Soundtrack и других специальных версий). Он делает реальные запросы с лимитом 1 запрос/с и изменяет выбранную базу, поэтому требует явного подтверждения:

```bash
python3 scripts/bootstrap_music.py --year-from 2026 --year-to 2026 --archive-out-of-scope --apply
```

Без `--apply` команда ничего не меняет. `--archive-out-of-scope` обратимо перемещает ранее загруженные альбомы других лет и специальных типов в корзину. Для безопасной проверки укажите путь к временной базе.

## MusicBrainz

Ключ и OAuth не нужны. Все обращения передают `User-Agent: WhatsNewChecker/2.0 (gavrevns@gmail.com)` и проходят через общий ограничитель не чаще одного запроса в 1,05 секунды. Временные ответы 429/503 и сетевые сбои повторяются ограниченное число раз; массовые операции продолжают работу с остальными записями и возвращают предупреждение в интерфейс.

Вместе с карточкой release group приложение проверяет Cover Art Archive. При наличии фронтальной обложки в SQLite сохраняются URL `https://coverartarchive.org/release-group/{release_group_mbid}/front-250` и относительный путь к локальному JPEG. Для фильмов TMDB Images аналогично используется постер `w185`, а квадратный `artistthumb` fanart.tv локально уменьшается до 200 px. Эти размеры превышают фактический размер иконок в интерфейсе, но заметно уменьшают локальный кэш относительно исходных изображений. Если изображение отсутствует, сохраняется пустое поле; временная ошибка вспомогательного сервиса не стирает уже известный файл. Документация: [TMDB Image Basics](https://developer.themoviedb.org/docs/image-basics), [Web Service API](https://musicbrainz.org/doc/MusicBrainz_API), [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API), [fanart.tv API v3.2](https://api.fanart.tv/) и [Music Artist Thumb](https://wiki.fanart.tv/ImageTypes/Music/artistthumb/).

ListenBrainz вызывается через `POST /1/popularity/release-group`. Идентификаторы разбиваются на пачки до 10 записей, каждый запрос выполняется только один раз с таймаутом 15 секунд. В рекомендациях сбой одной пачки не скрывает альбомы: у соответствующих карточек остаётся пустое количество прослушиваний, предупреждение сразу появляется в интерфейсе, а обработка продолжается. В SQLite сохраняются `total_listen_count` и время успешной проверки; `null` вместе со временем проверки означает, что ListenBrainz пока не располагает данными, и не вызывает повторный массовый запрос. После изменения Popularity API в июле 2026 приложение поддерживает заголовок `Authorization: Token ...` из `LISTENBRAINZ_USER_TOKEN`; без токена сохраняется совместимый публичный вызов, а HTTP 401 превращается в понятное предупреждение. Документация: [ListenBrainz Popularity API](https://listenbrainz.readthedocs.io/en/latest/users/api/popularity.html).

## API-ключи

Для локального запуска через `.app` скопируйте безопасный шаблон:

```bash
cp SECRETS.example SECRETS
```

Заполните локальный файл `SECRETS`:

```python
TMDB_API_KEY = "..."
OMDB_API_KEY = "..."
KINOPOISK_API_KEY = "..."
FANART_PROJECT_KEY = "..."  # project key из fanart.tv/get-an-api-key
LISTENBRAINZ_USER_TOKEN = "..."  # токен из listenbrainz.org/settings
CODEX_RECOMMENDATION_MODEL = "gpt-5.6-terra"
```

`SECRETS` добавлен в `.gitignore`; в Git включается только `SECRETS.example` с пустыми значениями. Приложение читает файл без выполнения его как Python-кода.

Переменные окружения имеют приоритет над `SECRETS`:

```bash
export TMDB_API_KEY="ваш_tmdb_ключ"
export OMDB_API_KEY="ваш_omdb_ключ"
export KINOPOISK_API_KEY="ваш_kinopoisk_ключ"
export FANART_PROJECT_KEY="ваш_fanart_project_key"
export LISTENBRAINZ_USER_TOKEN="ваш_listenbrainz_token"
python3 app/server.py --open-browser
```

Не храните реальные ключи в notebook, исходном коде или отслеживаемых конфигурационных файлах. Если ключ уже попадал в Git или был опубликован, одного добавления в `.gitignore` недостаточно — ключ необходимо перевыпустить.

TMDB не предоставляет структурированные награды кинофестивалей. Поле `awards_json` не затирается пустым ответом и допускает подключение будущего источника Cannes/Berlinale/Venice без миграции схемы.

## Codex SDK и подписка ChatGPT

LLM-рекомендации запускаются через официальный `openai-codex` в изолированном временном каталоге, с read-only sandbox и запретом подтверждений. SDK использует локальную авторизацию Codex, общую для CLI и IDE extension. При входе через ChatGPT расходуется доступ, включённый в план ChatGPT; `OPENAI_API_KEY` приложению не нужен. Обычный OpenAI Platform API имеет отдельный usage-based биллинг и в этой функции не используется. Структурированные ответы ограничены четырьмя JSON Schema: `app/movie_recommendations.schema.json`, `app/album_recommendations.schema.json`, `app/person_recommendations.schema.json` и `app/backlog_moods.schema.json`. Новые рекомендации затем независимо обогащаются через TMDB/OMDb/Кинопоиск либо MusicBrainz; карта настроений принимает только существующие локальные ID из текущего бэклога.

Модель по умолчанию — `gpt-5.6-terra`. Её можно изменить через `CODEX_RECOMMENDATION_MODEL` в локальном `SECRETS` или одноимённую переменную окружения.
