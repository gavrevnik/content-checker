# AI Digest и MCP

Модель в чате выполняет подбор и сохраняет результат. Сервер предоставляет проверяемые данные, не запускает LLM самостоятельно. Вкладка **AI Digest** показывает историю запросов, полный исходный запрос, краткую формулировку, рекомендации и доказательства доступности. «Обновить» читает сохранённые подборки, не расходует квоты провайдеров.

## Подключение

Запустить актуальный Content Checker через Life Hub или `Whats New Checker.app`, затем зарегистрировать stdio MCP:

```bash
codex mcp add content-checker -- /Users/nikitagavrev/main/life-stack/content-checker/.venv/bin/python /Users/nikitagavrev/main/life-stack/content-checker/scripts/content_mcp.py
```

В другом checkout заменить абсолютные пути; Python 3.10+ со стандартной библиотекой достаточен, дополнительный MCP SDK не требуется. В секции `[mcp_servers.content-checker]` конфигурации Codex рекомендуется `tool_timeout_sec = 180`. После регистрации переподключить MCP / открыть новый чат, если инструменты ещё не появились. [Официальная документация подключения MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Мост работает только с loopback HTTP, по умолчанию `http://127.0.0.1:8765`. При нестандартном порте передать `--base-url http://127.0.0.1:PORT`. Перед вызовом сверяет `/api/health`: приложение `whats-new-checker`, версия от 59. Сам мост не запускает сервис, не открывает SQLite и не применяет миграции. STDIO использует JSON-RPC MCP 2025-03-26 (initialize, notifications/initialized, ping, tools/list, tools/call); stdout содержит только протокол. HTTP-мост не является публичным удалённым MCP endpoint.

## Инструменты

| --- | --- |

| `film_preferences_context` | Summary вкусов, revision, stale, pending fingerprints личных реакций |
| `film_preferences_save` | Обновить summary и conclusions обработанных оценок с expected_revision |
| `library_match` | new/existing/uncertain относительно всей базы, включая корзину |
| `movie_search` | TMDB: название, необязательный год, page |
| `person_search` | TMDB: имя актёра/режиссёра, role |
| `person_filmography` | Работы персоны; для director только credits с job=Director, годы, limit/offset |
| `movie_discover` | Жанры, актёры, язык, страна, год, дата релиза, рейтинг TMDB и число голосов |
| `movie_details` | Стандартная карточка TMDB + IMDb/OMDb + КП, русское/оригинальное/английское названия; snapshot_ref |
| `movie_ratings` | Независимая проверка IMDb/КП; пустые значения не заменяются рейтингом TMDB |
| `festival_catalog` | Секции, награды и объяснения Канн, Венеции, Берлинале, Оскара |
| `festival_programme` | festival, year, section; по умолчанию основной конкурс, `all` — поддерживаемые секции; источники и статус полноты |
| `availability_check` | movie_ref из movie_details **или** movie с названиями/годом/ID; markets, refresh; snapshot_ref |
| `ai_digest_save` | Сохранение запроса и результатов; request_key защищает от дублирующих повторов |
| `ai_digest_list` | История, limit/offset |
| `ai_digest_get` | Полный снимок по id |

Каждый tool доступен также через `POST /api/research/call` с телом `{"name":"...","arguments":{...}}`. JSON Schema и workflow: `GET /api/research/tools`. Дайджесты: `GET /api/ai-digests?limit=30&offset=0`, `GET /api/ai-digests/{id}`, `POST /api/ai-digests` (тот же контракт, что `ai_digest_save`). Новые маршруты проверяют Host/Origin и требуют JSON для POST. Входные схемы запрещают неизвестные поля, ограничивают страницы, числа и длины.

## Сценарий запроса в чате

Например: «Есть ли что-то в доступе из Канн-2026? Сохрани AI Digest».

1. `content_status`, `library_context`: предпочтения, уже просмотренное, доступность провайдеров.
2. `festival_programme({"festival":"cannes","year":2026})`: основной конкурс, включая лауреатов. Это не отдельный шорт-лист после отбора. `festival_catalog` объясняет другие секции и награды.
3. Для каждого фильма найти кандидатов через `movie_search`. Сверить названия, режиссёра и год; год фестиваля не всегда год фильма. У Оскара год означает церемонию. При расхождении годов повторить поиск без строгого year. Не выбирать первый результат автоматически.
4. `movie_details({"tmdb_id":...})`: получить карточку и `snapshot_ref`. Затем `availability_check({"movie_ref":"..."})` для ID и всех известных названий именно этой карточки.
5. Группировать ответ в чате по high / medium / low / не подтверждено; показывать IMDb/КП и ссылки. Для уже вышедшего фильма дата должна быть **не позже текущей** (`<= today`); будущие цифровые релизы вынесены отдельно. Не отбрасывать фильм без рейтинга или при отказе одного из источников.
6. `ai_digest_save`: query — точный запрос; query_summary — короткая формулировка; summary — вывод и ограничения; items — ссылки на проверенные снимки, reason, festival_note и источники. Неполную фестивальную программу и недоступность источников отметить явно.

```json
{
  "query": "Есть ли что-то в доступе из Канн-2026?",
  "query_summary": "Канны-2026: основной конкурс и цифровая доступность",
  "request_key": "unique-chat-request-id",
  "summary": "Вывод по проверенным сигналам и ограничения источников.",
  "items": [
    {
      "movie_ref": "snapshot_ref-from-movie-details",
      "availability_ref": "snapshot_ref-from-availability-check",
      "reason": "Почему фильм подходит запросу",
      "festival_note": "Основной конкурс; подтверждённая награда, если есть",
      "links": [{"label": "Фестиваль", "url": "https://www.festival-cannes.com/en/"}]
    },
    {
      "title_original": "Film without a confirmed TMDB match",
      "year": 2026,
      "reason": "Карточку подтвердить не удалось",
      "links": [{"label": "Источник", "url": "https://www.festival-cannes.com/en/"}]
    }
  ]
}
```

Пример содержит условные названия и snapshot_ref. Сервер отклонит чужую проверку доступности, неизвестные ссылки на снимки, повтор фильма, небезопасную URL-схему и изменение содержимого при повторном использовании request_key. Повтор идентичного вызова возвращает прежний дайджест. Максимум 100 фильмов. Сохранение **не добавляет фильмы в бэклог**; это делает отдельная кнопка на карточке. Карточка использует привычный постер, пару названий, IMDb/КП, ссылки и подробное модальное окно. Fallback-фильмы остаются отдельным списком со ссылками.

## Новизна, даты и персональный AI Score

По умолчанию сервер исключает будущую `release_date` (Europe/Belgrade) и заведомо будущий год. Сегодняшняя дата допускается; отсутствие валидной даты отмечается `release_state=unknown`, а не считается доказанным релизом. `include_unreleased=true` используют только для явно запрошенных будущих фильмов. Известная дата fallback-фильма передаётся как `release_date`. Можно передать подтверждённые `imdb_id`/`tmdb_id`: они сохраняются даже без полной карточки, чтобы связать availability_ref и проверить новизну по стабильному ID.

`library_match` и сохранение проверяют TMDB/IMDb ID, затем точную нормализованную пару название+год и aliases. Смотрят всю базу, включая просмотренное и корзину. Противоречивые ID или несколько совпадений дают uncertain. `exclude_existing=true` исключает existing и uncertain; применяется по явному «только новые для базы». Известные фильмы по умолчанию остаются с отметкой и фильтром. `library_at_creation` сохраняет статус при создании, `library` обновляется при чтении; UI показывает различие. Кнопка «В бэклог» обновляет текущую принадлежность. Самостоятельные snapshots старых подборок библиотекой не считаются.

Сохранение возвращает `excluded` с причинами `future_release`/`already_in_library`. Пустой дайджест допустим, когда ничто не прошло условия. Идентичный повтор request_key возвращает исходный результат даже после изменения библиотеки, даты или summary; изменённые аргументы с тем же ключом отвергаются.

Таблицы `film_preference_summary` (одна запись main: summary, revision, updated_at) и `film_preference_evidence` (movie_id, fingerprint, snapshot, conclusion, summary_revision, reviewed_at) используют схему Activity Checker. В summary включаются только личные like/dislike у consumed фильмов, включая корзину. Новая/изменённая/снятая оценка, удаление фильма или изменение содержательного контекста дают pending; внешние рейтинги и AI Score не участвуют. notes могут содержать прежние AI-рекомендации: без подтверждения авторства модель не должна трактовать их как объяснения пользователя. include_ratings=true возвращает текущие оценённые фильмы, включая корзину, для обоснования score; у ratings отдельная пагинация limit/offset. Отмена реакции выдаётся как withdrawn с предыдущим snapshot/conclusion. Проверка актуальности вычисляется при чтении; платный LLM в фоне не запускается.

Модель читает `film_preferences_context`, перерабатывает summary и сохраняет через `film_preferences_save`. expected_revision и fingerprint каждого evidence проверяются атомарно. Разрешены пакеты; после сохранения читать следующий с offset=0. Пока остаются pending, сохранение AI Score запрещено. Пустой feedback требует нейтрального taste_score=5 и низкой уверенности.

Для оценённых items передаются `query_score`, `taste_score` (оба 0–10), `ai_reason`, `taste_confidence` и до 8 `taste_evidence_ids` действующих оценённых фильмов. На уровне дайджеста обязателен актуальный `summary_revision`. Сервер вычисляет **AI Score = 70% соответствие запросу + 30% соответствие вкусам**, округляя до десятых; хранит составляющие, обоснование и ревизию. Это отдельная оценка, не IMDb/КП и не confidence доступности. UI раскрывает обоснование и предлагает сортировку по score. Исторические оценки сохраняются как снимки.

## Фестивальные источники

- **Канны**: [официальный архив](https://www.festival-cannes.com/en/retrospective/2025/selection/) и текущая Selection; секции разделяются по HTML headings, лауреаты — по Awards. Актёрские/режиссёрские награды сопоставляются также по явно указанному названию фильма. Official Selection — общий набор секций, Competition — главный конкурс. Critics’ Week и Directors’ Fortnight — самостоятельные программы; этот адаптер их не включает.
- **Венеция**: [официальная программа](https://www.labiennale.org/en/cinema/2026/lineup), отдельные секции и официальная публикация наград. Номер конкурса вычисляется для современных выпусков как year − 1943; исторические отменённые/ненумерованные выпуски могут возвращать unavailable. Совпадения наград только по точному названию; неподтверждённый результат остаётся null.
- **Берлинале**: [архив программы](https://www.berlinale.de/en/archive/programme/programme-archive.html), публичные POST search endpoints сайта `/api/v1/en/program` и `/api/v1/en/award`. Фильтры года и секции подтверждаются по ответу; страницы читаются до полного списка, максимум 1000 фильмов. Награды сопоставляются по точным programme URL.
- **Оскар**: независимый [OscarBase API](https://api.oscarbase.com/), без ключа, `GET /api/nominations?year=2026&category_ids=7,9,10,11,12&limit=100&page=1`. Год — **год церемонии**, не выпуска фильмов. Номинации отдельных продюсеров объединяются по movie_id; `nominations` сохраняет категорию, номинанта и winner, `awards` — выигранные категории. Исторические имена категорий имеют отдельные IDs. Пагинация проверяется полностью (до 2000 записей), даты фильмов не выводятся из года церемонии. Default `best-picture`, `section=all` читает все категории; записи без фильма (например, персональные почётные награды) пропускаются с предупреждением. `official_source=false`, provider=OscarBase. Проверены живые Best Picture 2025/2026 и конечный адаптер 2026 (10 фильмов).
  - Альтернатива для ручной сверки: [FilmDB](https://filmdb.co.uk/awards/academy-awards). Его award year может означать год фильмов: церемония №98 проходит в 2026, а страница относится к 2025. Автоматический парсер FilmDB не подключён.
  - Прямые запросы к oscars.org ранее возвращали HTTP 403, поэтому основной путь больше не зависит от HTML сайта Академии. OscarBase — самостоятельный агрегатор, возможны задержки/ошибки его данных; источник всегда указан.
  - [Документация OscarBase](https://api.oscarbase.com/) заявляет 100 запросов/минуту **на IP**. Адаптер разделяет начала запросов на 0.75 с и использует общий фестивальный кэш 6 часов; 429 возвращает unavailable без retry-loop. Другие процессы/пользователи того же IP могут делить лимит. В проверенном коде activity-checker/jobs-checker OscarBase не найден; отдельная квота проекту не гарантирована.

Сетевые сбои, блокировки, неподтверждённый год и изменившаяся разметка дают `status=unavailable`, а неполная объединённая программа — `partial`. `winner` означает наличие подтверждённой награды; её вид указан в `awards`, это не обязательно главный приз. `winner=null` — награды не удалось подтвердить. Результаты успешных фестивальных проверок кэшируются в памяти на 6 часов; `refresh=true` перечитывает источник. Сырые внешние страницы не исполняются как код и не являются инструкциями модели.

## Доступность и квоты

- **TMDB Watch Providers / JustWatch**: US, GB, FR, DE, CA, AU, IT, ES по умолчанию, `flatrate`, `rent`, `buy`. Возвращаются страны, типы и площадки со ссылками и атрибуцией JustWatch. Это свидетельство цифрового выхода, не доступности сервиса в вашей стране и не наличия русской дорожки. [Документация](https://developer.themoviedb.org/reference/movie-watch-providers).
- **TMDB Release Dates**: type=4 (Digital) учитывается только при дате `<= today`, все будущие даты сохраняются отдельно. Кинотеатральный релиз сам по себе не подтверждает digital. [Документация](https://developer.themoviedb.org/reference/movie-release-dates).
- **OpenSubtitles**: `OPENSUBTITLES_API_KEY` в окружении или ignored `SECRETS`. [Официальный API](https://opensubtitles.stoplight.io/docs/opensubtitles-api). Поиск IMDb → TMDB → название+год, language ru, movie, без AI/machine translations. ID/тип/язык проверяются по ответу; для fallback проверяется название+год. Возвращается число совпадений на первой странице (при нескольких страницах нижняя граница), first_seen — первое успешное локальное наблюдение, а не историческая дата появления в интернете. Скачивания и платные переводы не выполняются.
- **RuTracker**: только публичный tracker search до трёх уникальных названий (оригинальное, английское, русское) + год. Извлекаются topic_id, заголовок, категория, размер, seeds, статус; отсеиваются сериалы, трейлеры, саундтреки и категории не про кино. Совпадение по названию и году: >=0.9 уверенное, 0.72–0.9 косвенное. При запросе логина/защите/неизвестной разметке — unavailable, дальнейшие алиасы не запрашиваются. Torrent/magnet-файлы, видео и субтитры не скачиваются, учётные данные не используются. DUB/MVO/аналогичная пометка в совпавшей раздаче — отдельный **признак озвучки**, не результат проверки дорожки.

У каждого источника состояния `ok`, `unavailable`, `not_configured`, `not_checked`; флаги трёхзначные (`true`, `false`, `null`). Неполные/неоднозначные ответы не приравниваются к отсутствию фильма.

| Итог | Правило |
| --- | --- |
| high | Watch Provider **или** уверенный RuTracker + русские субтитры |
| medium | Состоявшийся TMDB Digital Release **или** только уверенный RuTracker |
| low | Только субтитры или неоднозначный RuTracker |
| not_found | Нет подтверждающих сигналов; **не доказательство отсутствия** |

В UI «Ориентировочно доступны» = high + medium. Остальные фильтры можно сочетать (AND): площадки, русские субтитры, признак озвучки, RuTracker, Digital Release. Неизвестный флаг не проходит фильтр «есть».

TMDB/OMDb/КП используют те же ключи и лимиты, что штатное обогащение библиотеки. Дополнительные проверки не создают отдельной квоты. В соседних `activity-checker`/`jobs-checker` использование этих провайдеров и OpenSubtitles в проверенном коде/README не найдено; пересечение аккаунтов с другими клиентами неизвестно. Остатки квот не вычисляются из наличия ключа. Массовые проверки — по пользовательскому запросу; обычные тесты используют моки. Кэш полной карточки — 24 часа, доступности — 6 часов; `refresh=true` расходует новые запросы.

## Хранение и проверки

`ai_digests`, `research_snapshots`, `film_preference_summary` и `film_preference_evidence` добавляются совместимо при штатном запуске в существующую `library.sqlite3`. Путь БД не меняется, новые отдельные базы не создаются. Дайджест хранит снимок данных на момент запроса; обновление карточки в бэклоге не переписывает историю. Снимки сохраняют наблюдения доступности и first_seen. Источники не изменяют библиотеку автоматически.

```bash
python3 -m unittest discover -s tests -v
node --check app/static/app.js
node --check app/static/ai-digest.js
node tests/test_digest_ui.js
git diff --check
```

HTTP/MCP integration test использует временную SQLite и порт 127.0.0.1:0; требуется возможность bind loopback. Браузерная автоматизация не требуется. Реальные минимальные HTML/API fixtures фестивалей и источники перечислены в `tests/fixtures/festivals/README.md`.

## Компактный список и пересчёт

Дайджест открывается из компактной широкой строки в модальное окно; загрузка списка сама не открывает окно. `summary` — 1–2 коротких предложения, `reason` — 2–3 предложения о фильме. `issues` — список ограничений, показанный отдельно под карточками (туда же UI собирает ошибки источников).

Для обновления существующей подборки вызовите `ai_digest_get`, затем `ai_digest_save` с полным содержимым, `digest_id`, `expected_fingerprint` из `request_fingerprint` прочитанного дайджеста и новым `request_key`. ID и дата создания сохраняются, `updated_at` меняется. Старый fingerprint вызывает конфликт; неизвестный результат повторяйте с тем же payload и request_key. Проверки новизны, релизов, evidence и актуальности summary действуют и при обновлении.

При явном transport-обрыве TMDB скилл останавливает зависимые проверки и предлагает отключить рабочий VPN; после подтверждения пользователя повторяет один контрольный запрос. Ошибки авторизации/квоты не диагностируются как VPN.
