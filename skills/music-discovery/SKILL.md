# Музыкальные рекомендации и плейлисты

Веди подборку здесь в Codex. Используй локальный stdio MCP `personal-radar-youtube`
из соседнего `personal-radar/mcp-tools/youtube-local/`; облачный Radar не управляет
этим YouTube-аккаунтом. Не запускай фоновые задачи, LLM API или массовые импорты.
Инструкции по настройке и восстановлению: [локальный MCP](../../../personal-radar/mcp-tools/youtube-local/README.md).

## Контекст и отбор

- Начни с исходного запроса: настроение, ситуация, жанры, языки, знакомые/новые
  исполнители, допустимость лайвов/ремиксов, число песен и целевой плейлист.
  Если число не задано, предложи 15 песен; новый плейлист по умолчанию `llm-discovery`.
  Одноимённый пользовательский плейлист не считается доступным для записи.

- Получи `music_preferences_context` из Content Checker. Это локальные альбомы, личные
  `reaction=like/dislike`, заметки и отслеживаемые исполнители. Дочитывай независимые
  `albums.next_offset` / `artists.next_offset` при необходимости; сообщи ограничение, если
  использована только часть.

  Отслеживаемый артист — интерес, а пустая реакция — неизвестно. AI score и наличие в
  библиотеке не равны лайку. Если MCP ещё не обновлён, используй тот же инструмент через
  loopback `POST /api/research/call` на URL Content Checker из Life Hub registry.

  Сервис должен работать; не импортируй initializer приложения и не мигрируй БД для чтения.

- Прочитай `personal-radar/knowledge/preferences/music-preferences.yaml`, при необходимости
  связанные коллекции `music-artists-of-interest` / `liked-albums` через существующий
  Radar retrieval или локальные YAML из основного каталога. Локальные реакции не записывай в Knowledge.

- Вызови `youtube_auth`, при необходимости с `refresh=true`; затем
  `youtube_get_liked_videos`. Для отрицательных сигналов доступно `rating="dislike"`.
  Учитывай музыкальные записи, отделяя прочие понравившиеся видео. Проверяй
  `complete`, `started_from_first_page`, `next_page_token`, `error`; API не обещает
  полную историю прослушиваний, все реакции YouTube Music или отсутствие песни в аккаунте.

- До формирования рекомендаций и вызовов `youtube_search_music` найди целевой плейлист через
  `youtube_get_my_playlists` с пагинацией либо используй известный из текущего разговора
  `playlist_id`. Название не является уникальным ID; при нескольких совпадениях уточни цель.
  Прочитай его состав через `youtube_get_playlist_tracks`, дочитывая `next_page_token` до
  полного результата.

  При пополнении `llm-discovery` это обязательный контекст для отбора. Если плейлиста ещё
  нет или пользователь явно просит новый, учитывай отсутствие существующего состава. При
  ошибке/лимите/неполном чтении сообщи ограничение и не обещай отсутствие дублей.

- Исключай уже имеющиеся песни до поиска, чтобы не тратить на них поисковую квоту.
  Сверяй video ID, когда он известен, и исполнителя/название/версию: разные video ID
  могут относиться к одной записи. Не предлагай клип или переиздание той же песни
  как новую рекомендацию; альтернативную версию включай только по смыслу запроса
  и явно обозначай её. Наличие песни в плейлисте само по себе не равно лайку.

- Учитывай явные ограничения текущего запроса раньше общих вкусов. Объясняй каждую
  рекомендацию через конкретный сигнал: альбом/исполнитель/лайк/вводная запроса;
  не придумывай личные предпочтения. Разнообразие и новизна — по запросу, не жёсткий
  жанровый фильтр. При запросе нового исключай известные записи и дубли по имеющимся данным,
  но не обещай «никогда не слышал» при неполной истории.

## Поиск и предпросмотр

Для каждого финального кандидата вызови `youtube_search_music(artist, title)`. Сравни
несколько результатов: исполнитель, название, канал, длительность и `version_hints`
(`topic_recording`, `official_audio`, `music_video`, `live`, `cover`, `remix`, `unknown`).
Это эвристики метаданных, не доказательство официальных прав.

Не выбирай первый результат автоматически и не подменяй неизвестную запись кавером. YouTube
Data API ищет video ID; присутствие видео не гарантирует каталог/регион YouTube Music.

Пополняй плейлист только при `managed=true`, если API подтвердил владельца
и приватность. Если существующий пользовательский плейлист не managed,
предложи новый приватный;
не обходи ограничение ручным API или изменением registry.

Вызови `youtube_preview_playlist_additions(video_ids, playlist_id)`; для нового плейлиста
опусти `playlist_id`. Один preview вмещает до 25 песен и действует 1 час. Это повторная
проверка актуального состава перед записью; она не заменяет предварительное чтение плейлиста
до отбора рекомендаций.

Дополнительно исключи совпадения по исполнителю/названию/версии: серверный preview проверяет
дубли по video ID. Покажи конкретный состав: артист — песня, версия, причина рекомендации,
ссылка; отдельно дубли и недоступные записи. Не добавляй ничего при запросе только
рекомендаций.

## Подтверждение и запись

Перед записью получи явное подтверждение конкретного состава и целевого плейлиста.
Если оно уже дано в текущем разговоре для этого состава/цели, не спрашивай повторно.
Фраза «порекомендуй и пополни» разрешает подготовку, но сама по себе не подтверждает
ещё неизвестные песни. Не устанавливай `confirmed=true` от собственного имени.

- Новый плейлист: `youtube_create_playlist(title, request_id, dry_run=true)`,
  затем после подтверждения тот же title с `dry_run=false, confirmed=true`.
  Используй полученный `playlist_id`; название по умолчанию `llm-discovery`.

- Добавление: `youtube_add_tracks_to_playlist(playlist_id, preview_id, request_id,
  dry_run=true)`, затем подтверждённая запись с `dry_run=false, confirmed=true`.
  Для create и add используй разные уникальные request ID, например UUID.
  Сохраняй ID при повторном чтении результата. Подставляй только `eligible_video_ids`
  утверждённого preview; реальный состав сервер берёт из него сам.

- Для >25 песен дели подтверждённый состав на небольшие партии и остановись на первой
  ошибке. Сначала покажи квотную стоимость: insert плейлиста и каждой песни — 50 units.
  Локальные дневные лимиты по времени Pacific: 20 поисков, 300 вызовов API
  и 2500 insert units. Они не показывают остаток квоты Google Cloud.
  Cloud Radar может использовать тот же проект.

- При `partial` сообщи ID реально добавленных песен и оставшуюся часть. При `pending`/`unknown`
  не повторяй запись с новым ID. Прочитай состояние аккаунта и журнал;
  затем выполни локальную ручную сверку. Не удаляй receipts/registry для обхода блокировки.

- Истёкший preview обнови; если состав изменился, подтверди изменения. OAuth обновляется
  локальной командой `.runtime/youtube-venv/bin/youtube-auth` в Personal Radar;
  при необходимости `--force`. Не передавай коды/токены через чат.

Заверши ссылкой на плейлист, числом добавленных/пропущенных записей и существенными
ограничениями. Различай успешное создание и частичное пополнение. Не меняй лайки,
подписки, privacy или существующие записи; не сохраняй рекомендации в Content Checker
или Knowledge без отдельного запроса.

После каждой итерации, в которой обращался к YouTube API, обязательно добавляй в ответ в
чате кликабельную ссылку: [Проверить квоты YouTube
API](https://console.cloud.google.com/apis/api/youtube.googleapis.com/quotas?project=acitivity-checker).
Это относится к чтению лайков/плейлистов, поиску, предпросмотру с API-проверками, созданию и
пополнению плейлистов, включая частичный результат или ошибку.

Ссылка нужна и после подбора без записи. Показывай её обычной Markdown-ссылкой, не в блоке
кода. Чисто локальная работа без YouTube API, включая `youtube_quota_status`, сама по себе
этого не требует.

Не выдавай локальные счётчики за фактический остаток проекта Google; пользователь проверяет
его по ссылке. Автоматическое чтение Cloud quota не подключай без отдельного запроса.
